# Manual UI pass: all roles, EN + ID (TAQ-14)

Run 2026-11-23 against the stack of the load test (so with about 4 300 scans and 240 incidents
in it), Chrome 1366x900 plus 390 px width, production nginx/CSP, Keycloak login with TOTP.
Accounts: operator (platform-admin) and admin, supervisor, HR, client-readonly of client 1,
and admin, supervisor, HR, client-readonly of client 2 = 9 logins. Every page below was opened
in English and in Bahasa Indonesia (language switch stored in the browser, plus the header toggle
used live), with a screenshot, console and network capture and checks for raw translation keys,
text in the wrong language and horizontal overflow.

Matches `web/src/lib/roles.ts` for every role. Also checked by hand-written script:

* SOS fired from a tablet appears in the supervisor's banner within the poll interval, the
  banner switches language live, "Acknowledge/Tanggapi" clears it with a toast; no horizontal
  overflow at 390 px on home, patrol, incidents, attendance; sign-out ends the Keycloak session
  (protected URL redirects to the login page); realm picker, password + OTP login.
* Both realms are isolated (client 2 sees none of client 1's site).

Findings: no raw translation keys and no wrong-language text on any page (the only hits were the
loan words "Shift", "Host", "E-mail", identical in both languages). One defect, filed:
**TAQ-41** (platform-admin-only user: 403 on `GET /sites` on every page, header shows "No sites yet").

Not covered here:

* Tablet app (hardware, camera/QR, kiosk mode, FCM): needs a device.
* Real e-mail/WhatsApp delivery and browser push; destructive/CRUD flows were not driven through
  the UI (guards, routes, schedules, users, device approval were created through the API by the
  load-test setup and displayed correctly).
* Orca's embedded browser rejects the stack's private CA (ERR_CERT_AUTHORITY_INVALID), so the pass
  was driven with an installed Chrome (certificate errors ignored) instead.
