# Gap analysis & enterprise-readiness audit — 2026-10-09

Snapshot audit of `init` @ ea14147 plus the (then uncommitted) mobile v1 tree.
Five read-only reviews: PRD traceability, backend quality/security, web + mobile
quality, infra/ops/delivery. Every finding has an ID; fixes reference it in
commits and `PROGRESS.md`. Status is tracked in **PROGRESS.md**, not here.

**Verdict:** functionally close to the PRD (all FR areas implemented end-to-end),
but **not enterprise-ready and not go-live-ready**: the full stack has never been
booted, alerting (SOS/SLA) has single points of failure, field evidence can be
forged or replaced, there is no off-host backup and no monitoring.

Severity: **B** = go-live blocker, **H** high, **M** medium, **L** low.

## 2. Backend (BE)

Security
| ID | Sev | Finding |
|---|---|---|
| BE-S1 | H | Guard identity is trusted from `X-Guard-ID` (PIN checked only on the tablet); client event times up to 7 days back decide on-time vs late; raw QR codes shipped to tablets; no GPS plausibility check |
| BE-S2 | M | Idempotent replay (`ON CONFLICT DO NOTHING` → `Get*(id)`) does not check site: a known UUID returns another site's/realm's record (incident, SOS, defect, visitor, scan) |
| BE-S3 | H | `PUT /settings/channels` + `POST /settings/channels/test`: change host/URL while keeping the stored secret → exfiltrate WhatsApp token / SMTP password, SSRF to internal services, raw error echoed. Any realm's admin can do it (D-005) |
| BE-S4 | M | `POST /media` overwrites existing objects → evidence photos replaceable; photos bucket unversioned |
| BE-S5 | M | Global 11 MB body limit on all JSON routes, no field length limits, no rate limiting (API or nginx) |
| BE-S6 | M | JWT: `typ` not checked (ID tokens accepted), roles not bound to `azp` (web users can use the tablet client's password grant and skip OTP) |
| BE-S7 | H | Go 1.22 EOL; golang-jwt v5.2.1 (CVE-2025-30204), Fiber 2.52.5 (BodyParser CVE), go-redis 9.6.1 (CVE-2025-29923); no govulncheck in CI |
| BE-S8 | M | Audit middleware uses Fiber buffers after the handler returns (data race / corrupted rows); IP from spoofable X-Forwarded-For; fire-and-forget; no before/after; table writable by the app |
| BE-S9 | M | PII: no retention/cleanup, visitor ID numbers plaintext, EXIF kept, `/media/url` lets HR/client fetch any photo kind (UU PDP 27/2022) |
| BE-S10 | L | `pg_dump --dbname=<url with password>` in argv; app uses the Postgres superuser; Fiber default error handler leaks `err.Error()`; cross-tenant unique `employee_id` |

Reliability
| ID | Sev | Finding |
|---|---|---|
